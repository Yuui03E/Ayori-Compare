# Implementation decisions

The approved review identified several details that needed explicit engineering choices. These decisions describe the current implementation and its limits.

- **Double right click:** two right clicks within 500ms and 6 CSS pixels toggle a saved zoom/pan/fit snapshot. Default target is 200%; the persisted desktop target accepts integer 1–12800%. The clicked source coordinate stays anchored, including the right split panel and fractional DPI. Panning and same-scene A/B switching retain the return view. Manual zoom, Fit, scene/base-size changes, canvas resizing and entering/leaving split layout invalidate it. Home/resume retains it within the session.
- **Mouse gesture coordination:** right hold waits 220ms when double-click zoom is enabled; a drag beyond 6 CSS pixels starts the loupe immediately. Disabling the gesture restores immediate right-held loupe. Capture loss, blur, dialogs and navigation cancel pending gestures; quick clicks never flash the loupe. Keyboard-held loupe and right-held loupe release independently. The offline viewer shares the gesture and renderer, with a session-specific target, canvas focus after editing, and readout updates after zoom/restore without pointer movement.
- **Resolution explanation:** resampling behavior is unchanged. Independent maximum scene width/height define a common normalized rectangle, stretching different aspect ratios. Auto uses nearest at zoom ≥1, otherwise bilinear with trilinear mipmap minification; explicit Bilinear keeps smoothing. Originals are never resized for readout. RGB8 sRGB SSIMULACRA2 independently resizes source 1 to each candidate with Catmull–Rom. The guide states these distinctions and recommends matching aspect/crop.

- **Matching:** exact lowercase stems win. Unique trailing integer matches fill missing cells or form additional scenes. Multiple candidates for one source/frame are reported and skipped; no arbitrary file is selected. Exact scene rows sharing a frame number are not merged. Folder scans are nonrecursive. A workspace contains either files or folders; Alt-append preserves source order and rejects mixed types. There is no eight-source import limit following the user's large-collection request.
- **Source values and color:** decoded RGB(A) channels remain unchanged for readout. The initial display policy treats channels as SDR encoded RGB without ICC/gamma transforms, orientation changes, or HDR tone mapping. Inspection differences use these encoded channels, with a luma heatmap defined as `abs(YA - YB)`. Alpha is composited over a checkerboard for ordinary viewing; difference and banding tools inspect RGB independently of alpha. SSIMULACRA2 is explicitly computed on RGB8 sRGB against slot 0; 16-bit data is rounded for scoring only. This policy is exposed through View options and the comparison guide.
- **Precision:** 16-bit images use normalized 16-bit textures when supported. Fallback downshifts only the GPU preview; original typed arrays remain available for exact `RAW16` readout. RGB8, 10-bit equivalents, and HEX are derived values. A persistent label explains the reduced preview precision.
- **Resolution:** UV normalization follows the PRD. Coordinates/readout/loupe use each source's dimensions. The grid follows the displayed source (A in difference modes). The loupe magnifies the current view by eight, and uses `texelFetch` independently of the preview filter. Split panels share the same coordinate transform.
- **Quadrants:** fixed slots 0, 1, 2, 3 in top-left, top-right, bottom-left, bottom-right order. Absent slots display a patterned placeholder. A/B source selection still applies to two-source modes and the loupe.
- **Lifetime:** the renderer owns active-scene textures and original typed arrays. Scene changes release them; async generations discard obsolete decode results. Four concurrent decodes and one metric job are allowed. Metric reference preprocessing is cached for at most two target resolutions. Large-image limits are 64 megapixels, 32768 pixels per dimension, and 512 MiB compressed file size; GPU-specific limits are checked separately. A numeric total process-memory budget is not yet proven.
- **Live updates:** watch parent directories to survive atomic file replacement, filter to active-scene paths, debounce for 150 ms, and retry transient decode failures three times. Reloads preserve mode/zoom/pan. Metrics carry scene and revision identities so obsolete badges are discarded.
- **Export:** self-contained HTML embeds deflate-compressed, base64 AYRI packets and a compiled copy of the same WebGL renderer. It preserves decoded 8/16-bit samples and includes all scenes with source selection, core modes, pan/zoom, loupe, and source readout. No absolute input paths are included. Modern WebGL2 and `DecompressionStream` support are required. Export reads current disk files and writes through a temporary file before replacing the selected destination.
- **Toolchain:** AVIF decoding uses `avif-decode` 3 / rav1d instead of the original encoder-only `image/avif` setting. This requires Rust 1.98+ and NASM 2.14+ on x64. The repository's desktop launcher automatically uses the optional ignored `.tools/nasm-3.02/nasm.exe` when available.
- **AVIF isolation:** rav1d 1.1.0 documents a process-abort path for a malformed AV1 payload. AVIF file decoding therefore runs in a hidden worker invocation of the same executable. A worker crash is returned as an image error; the main window survives. PNG/JPEG/WebP remain in the bounded in-process pipeline. This avoids a separate runtime binary but adds AVIF startup overhead.
- **PNG decoder selection:** measured release benchmarks favored the existing `image` / `png` decoder over the roadmap's zune-png choice (18.39 ms versus 38.31 ms median for the same four-frame corpus). The selected decoder retains CRC validation, expands palette/low-bit-depth inputs, preserves 16-bit samples, and records original IHDR bit depth separately. Consuming RGBA conversion avoids cloning already-RGBA images. Both the decision and performance claims are backed by correctness tests and the `benchmark` Cargo example.
- **Windows frame transfer:** WebView2's shared-buffer API delivers AYRI as a read-only `ArrayBuffer`; capability detection keeps the raw binary response for Linux and older WebView2. COM objects remain on the window thread, with a duplicated mapping handle used for worker-thread copying. The renderer owns each script mapping until replacement/removal; stale, cancelled or invalid packets are released immediately. Native reuse requires explicit acknowledgement after `releaseBuffer` detaches the JS view. At most one idle mapping up to 32 MiB is cached, and page navigation clears native state. This avoids the slow WebView2 custom-protocol body transfer while retaining source precision; it still includes a native pixel copy and GPU upload.

These choices do not establish that performance, file-size, color-management, or platform release targets have been achieved. Consult `PROGRESS.md` for measured results.

## Large collections and configurable controls

- The logical source list is independent of the eight shader samplers. Small comparisons keep all sources ready. Larger ones retain at most eight images: selected A/B, previous flicker source, fixed sources 1–4 in quadrant mode, then nearby sources. Four frontend loads are scheduled at a time; selecting a cold source requires decode/transfer/upload. Original sample precision is unchanged, and absent frames differ explicitly from images waiting to load.
- A background header pass obtains all scene dimensions (including AVIF metadata). The base uses the independent maximum width/height across the scene, so cache eviction does not alter physical zoom or normalized alignment. File changes invalidate dimension and pixel work separately. Watcher registration runs off the interaction thread.
- Large comparisons score the selected A/B candidates against source 1 on demand. Scene-local scores remain visible after visiting another source; revisions prevent outdated jobs from publishing after selection, reload or disposal. The metric worker checks revision and scene identities between candidates; an already-running candidate can finish before cancellation takes effect.
- Export retains every exact packet and its dimensions. The offline viewer has searchable A/B selectors and the same bounded resident set. Its encoded payload size still scales with the entire matrix. Desktop shortcut preferences are device-local and are not embedded in shared HTML; the viewer keeps standard shortcuts.
- There are 57 editable keyboard actions, including held loupe, source/scene navigation, imports, browsing, A/B exchange, zoom, filtering and adjustment controls. Assignments and interface preferences use versioned local storage. Conflicts and reserved focus/window keys are rejected; users can clear, individually reset or reset all assignments. Unsupported/corrupt settings recover to defaults; a storage failure is shown explicitly. Text fields retain ordinary editing keys, Tab retains focus navigation, and Escape can restore hidden controls.
- Tooltips appear on hover or keyboard focus and display current assignments. Settings expose tooltip and HUD auto-hide preferences. Native modal dialogs trap focus; source browsing pages large lists in groups of 100 without loading every image.

## Compact workspace and help (subsequent user decision)

- Replaced the paired metadata cards, side dock and bottom strip with one 44px top bar, including the native window controls. A/B chips show names and compact hover/focus metadata; inspection modes, scene stepping, fit/100%, pixel readout, copy, view options, import and help remain directly accessible. The original fonts and palette are retained. No permanent status panels cover the comparison.
- View options and import use native light-dismiss popovers; scene search shares the same behavior. Escape and outside clicks dismiss them, reopening is supported, and Escape restores trigger focus. Hover help uses compact spacing. Keyboard focus and open popovers prevent idle hiding; text entry does not run global comparison shortcuts.
- Help initially displays 12 essential editable actions in task order. The remaining bindings are opt-in through Show more shortcuts or search, preserving version-1 preferences instead of resetting existing custom keys. App usage and comparison guidance have dedicated pages; both explain mouse alternatives and current keys where relevant.
- The comparison guide explains same-frame/crop alignment, normalized resolution, fine detail and ringing, grain, gradients/shadows/chroma, difference gain, reference-relative RGB8 SSIMULACRA2 and SDR/preview limits. Enhancement views are described as inspection aids, not quality verdicts.

## Adjustable black chrome and application navigation

- The user requested a 16–44px bar range, pure-black theme, correct Ayori capitalization, application shortcuts including Q to quit, and a Home route. Default height is 32px; integer slider values and presets persist locally. At less than 24px, icons and labels compact without removing core controls. Menus and help retain normal readable sizing. Bar, primary panels and canvas surround are black; diagnostic missing/alpha patterns and A/B accent colors remain meaningful.
- Q quits, Ctrl+M minimizes, F10 maximizes/restores and Alt+Home returns Home. Existing native window permissions suffice. A small App-key row links to these editable bindings without expanding the essential comparison list. Input fields, shortcut recording and modal/popup interactions suppress comparison/application keys.
- Shortcut payload version 2 adds the four application actions. Version-1 assignments are validated and migrated without being overwritten; a new default that conflicts with a saved key is left unassigned. Existing cleared bindings remain cleared. Interface height values are clamped and invalid values recover to 32px.
- Home is an in-session navigation state, not destruction of the comparison. Decoding and file watching retain existing ownership rules. Resume restores the same resident frames and view. A navigation revision prevents an older import completion from overriding a later Home request. Starting a successful new comparison replaces the session; cancelling an import leaves it resumable. Sessions are not persisted across quitting.
- Retained all five inspection modes, exact readout, explicit missing cells and the comparison guide. Added an equals cue and explanatory tooltip when A and B are the same source, avoiding silent self-comparison. Secondary source indices/count labels compact at 16px rather than crowding the row. No additional analysis mode or score was added without an identified comparison need.
