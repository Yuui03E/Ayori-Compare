# Implementation decisions

The approved review identified several details that needed explicit engineering choices. These decisions describe the current implementation and its limits.

- **Matching:** exact lowercase stems win. Unique trailing integer matches fill missing cells or form additional scenes. Multiple candidates for one source/frame are reported and skipped; no arbitrary file is selected. Exact scene rows sharing a frame number are not merged. Folder scans are nonrecursive. A workspace contains either files or folders; Alt-append preserves source order and rejects mixed types or a ninth source.
- **Source values and color:** decoded RGB(A) channels remain unchanged for readout. The initial display policy treats channels as SDR encoded RGB without ICC/gamma transforms, orientation changes, or HDR tone mapping. Inspection differences use these encoded channels, with a luma heatmap defined as `abs(YA - YB)`. Alpha is composited over a checkerboard for ordinary viewing; difference and banding tools inspect RGB independently of alpha. SSIMULACRA2 is explicitly computed on RGB8 sRGB against slot 0; 16-bit data is rounded for scoring only. This policy is exposed through the source-RGB status and keyboard help.
- **Precision:** 16-bit images use normalized 16-bit textures when supported. Fallback downshifts only the GPU preview; original typed arrays remain available for exact `RAW16` readout. RGB8, 10-bit equivalents, and HEX are derived values. A persistent label explains the reduced preview precision.
- **Resolution:** UV normalization follows the PRD. Coordinates/readout/loupe use each source's dimensions. The grid follows the displayed source (A in difference modes). The loupe magnifies the current view by eight, and uses `texelFetch` independently of the preview filter. Split panels share the same coordinate transform.
- **Quadrants:** fixed slots 0, 1, 2, 3 in top-left, top-right, bottom-left, bottom-right order. Absent slots display a patterned placeholder. A/B source selection still applies to two-source modes and the loupe.
- **Lifetime:** the renderer owns active-scene textures and original typed arrays. Scene changes release them; async generations discard obsolete decode results. Four concurrent decodes and one metric job are allowed. Metric reference preprocessing is cached for at most two target resolutions. Large-image limits are 64 megapixels, 32768 pixels per dimension, and 512 MiB compressed file size; GPU-specific limits are checked separately. A numeric total process-memory budget is not yet proven.
- **Live updates:** watch parent directories to survive atomic file replacement, filter to active-scene paths, debounce for 150 ms, and retry transient decode failures three times. Reloads preserve mode/zoom/pan. Metrics carry scene and revision identities so obsolete badges are discarded.
- **Export:** self-contained HTML embeds deflate-compressed, base64 AYRI packets and a compiled copy of the same WebGL renderer. It preserves decoded 8/16-bit samples and includes all scenes with source selection, core modes, pan/zoom, loupe, and source readout. No absolute input paths are included. Modern WebGL2 and `DecompressionStream` support are required. Export reads current disk files and writes through a temporary file before replacing the selected destination.
- **Toolchain:** AVIF decoding uses `avif-decode` 3 / rav1d instead of the original encoder-only `image/avif` setting. This requires Rust 1.98+ and NASM 2.14+ on x64. The repository's desktop launcher automatically uses the optional ignored `.tools/nasm-3.02/nasm.exe` when available.
- **AVIF isolation:** rav1d 1.1.0 documents a process-abort path for a malformed AV1 payload. AVIF file decoding therefore runs in a hidden worker invocation of the same executable. A worker crash is returned as an image error; the main window survives. PNG/JPEG/WebP remain in the bounded in-process pipeline. This avoids a separate runtime binary but adds AVIF startup overhead.

These choices do not establish that performance, file-size, color-management, or platform release targets have been achieved. Consult `PROGRESS.md` for measured results.
